# AI Chat

The chat gives you access to text neural networks: ask, explain, translate, write
code, go through a document or a picture. It differs from the generator
fundamentally: **the chat is text-only**, there are no "Images" or "Video" tabs
here, even though the screen layout looks similar.

![AI chat](/assets/docs-pages/screens/07-01-chat-main.en.webp)

Three parts: the list of conversations on the left, the conversation in
the middle, the settings on the right.

<Callout type="warning">
  **The chat has its own header, and on a wide screen there is no globe in it.**
  To change the language, leave the chat for any other page — or open the side
  menu (the button at the top left): the language switcher is always at the
  bottom of that menu. See [Profile and settings](/en/docs/profile).
</Callout>

Here is how it looks on a phone: the side menu opened straight from the chat,
every section of the site inside it, and **at the very bottom, below the rule,
the globe with the current language**.

![The side menu with the language switcher, opened from the chat](/assets/docs-pages/screens/14-01-mobile-chat-nav-drawer.en.webp)

## The right panel: four blocks

**Model · Ready-made prompts · System prompt · Additional.** The last block does
not always appear — it is assembled from what the selected model can do.

<Callout type="warning">
  **This is the main answer to "why don't I have that button".** The reasoning,
  tools and web-search toggles, the parameter sliders, accepting attachments —
  all of these are **capabilities of a particular model**. If the model does not
  have one, the control is not "hidden" and not "broken" — it does not exist.

  Hence the working rule: if a toggle is missing, change the model rather than
  hunt for a setting.
</Callout>

## Choosing a model

A list of models with search and tags, as in the generator. Text models are
priced **per thousand tokens**, and the price is on the card.

<Callout type="tip">
  Tags are a filter by task. Need a picture or a screenshot analysed — take
  a model tagged **VISION**, otherwise the attachment simply won't be accepted.
  Need long documents — look at **LONG-CONTEXT**. Comparing models is easier
  in the [catalog](/en/docs/catalogs), where each has a description.
</Callout>

## Ready-made prompts: roles for the assistant

![Ready-made prompts and roles](/assets/docs-pages/screens/07-03-chat-prompts-roles.en.webp)

These are not sample questions but **system prompt templates** — ready roles:
data analyst, product manager, technical writer, contract editor, scriptwriter,
translator, senior developer and others. Roles have search, categories and
**bookmarks**: a marked role rises in the list.

<Callout type="tip">
  **Open a role's card — the full text of its prompt is there, and it can be
  copied.** This is the best textbook on system prompts the service has: look
  at how a ready role is written and write your own by that example.
</Callout>

The list of roles is **loaded from the server**, so it has a loading state and
an error state with a "Retry" button. Roles keep being added over time, and
the list height is limited — if it looks like there are only three of them,
scroll.

## The system prompt

The "Set the assistant's behavior…" field is an instruction applied
**at the start of every message in the conversation**, not once.

<Callout type="warning">
  **The system prompt is billed separately and on every request.** A three-screen
  instruction will cost money each time you say "hi". A short system prompt is
  both cheaper and more effective.
</Callout>

The eraser on the right of the field appears only when there is something in
it, and it also **clears the selected role** — text and choice at once. There
is no separate "remove role" button, which is not obvious.

## Additional: answer parameters

- **"Max answer tokens"** — a slider whose bounds are set by the model.
- **"Answer detail"** — three buttons: **Brief · Medium · Detailed**.
- **"Reasoning"** — a toggle on models that can do it. Turning it on reveals
  **"Reasoning effort"** with a set of steps.
- **"Tools"** — a toggle on models that support tools.

<Callout type="warning">
  **The reasoning effort steps come with the model, and each costs differently.**
  Different models have a different number of steps, so a universal
  "low / medium / high" does not exist. One rule holds: the higher the step,
  the more expensive the request.
</Callout>

Reasoning helps on logic problems and gets in the way on simple ones, where it
only burns tokens. For "rewrite this email more politely" it is better off.

## Tools: when the answer is drawn, not written

With tools on, the model can answer not with text but with a **widget**: a chart
or a table, a plan with step progress, source cards, a list of options to choose
from, an order summary, a carousel of cards, an image, a video or audio player,
points on a map, terminal output.

**Example.** "Compare three plans by price and limits" with tools on gives a real
table rather than text with asterisks. "Plot sales by month" gives a real chart.

<Callout type="tip">
  Tools are not "smarter", they are **clearer**. Turn them on when you expect
  a comparison, a list of steps or numbers; turn them off for ordinary
  conversation.
</Callout>

## What else an answer can render

An answer is not plain text. It supports GitHub-style markup (tables,
checklists, strikethrough), **mathematical formulas** instead of raw LaTeX,
and **code with highlighting and a copy button**.

<Callout type="tip">
  **Few people know the chat draws diagrams.** Ask for a mermaid diagram —
  "draw the order process as a mermaid diagram" — and you get a finished
  flowchart as a picture right in the answer, not text made of dashes.
</Callout>

## Buttons around the input field

To the left of the field — a **paperclip** ("Attach a file (PDF, text, code)")
and a **web search icon**. To the right — a **microphone** ("Voice input")
and **Send**. Next to them — **Clear prompt**.

### Web search

![Web search in the chat](/assets/docs-pages/screens/07-12-chat-web-search.en.webp)

The globe icon makes the model **go to the internet before answering**.
The tooltip spells it out: "Search the web before answering. Applies to one
message, +N coins per request" — the surcharge is written right there.

<Callout type="tip">
  The key phrase is **one message**. This is not a mode that stays on: for
  the next question you press the button again. Turn it on where freshness
  matters: prices, news, versions, documentation.
</Callout>

Some models search the internet by themselves — they have no toggle and don't
need one.

### Attachments

You can attach with the **paperclip or by dragging files into the window**.
The formats are listed in the paperclip's tooltip: pictures, PDF, text and code,
audio, video. Every file has its own status — queued, uploading, uploaded, error,
cancelled; an upload can be retried, cancelled, or the file removed.

<Callout type="tip">
  **The fastest way to show the chat one of your older works is to paste its link
  straight into the message text.** The service downloads the file and attaches
  it itself. Almost nobody knows this. And a picture from the generator can be
  sent to the chat with the single "Discuss with AI in chat" button — see
  [Generator](/en/docs/generator).
</Callout>

**An attachment can be refused for three different reasons, and each is cured
differently:**

1. **too many files in one message** — the limit is substituted into
   the message; when dragging a batch, only the first ones are added;
2. **the format is not supported at all** — the message lists what is allowed;
3. **the model cannot read such files** — the format is fine, but the selected
   model does not work with it. Only changing the model helps here.

Attachments are **estimated in advance and cost coins**: if the balance is short,
the service says outright what the files were estimated at and offers to remove
some or top up.

## What a message costs

The mechanics are the same as for image generation: before sending, coins are
**reserved with a margin** — based on your text, the system prompt and
the maximum answer length. After the answer, the **actual usage** is charged and
the difference returns. Attachments add a separate sum, and reasoning and web
search make a request more expensive.

<Callout type="tip">
  **The cheapest way to hold a long conversation is to start a new one for a new
  topic.** The estimate includes the whole context, and context grows with
  the length of the thread: the twentieth message costs noticeably more than
  the first. More about coins — [Coins and limits](/en/docs/coins).
</Callout>

## A live answer and what is under it

![A live reply in the chat](/assets/docs-pages/screens/07-09-chat-live-answer.en.webp)

The answer types itself out in front of you. Under it — the **token count** and
the **generation time**; an answer made with search carries a note saying so.

A message has seven states: sending, request accepted, generating an answer,
**recovering the answer**, answer ready, generation error, cancelled.

<Callout type="tip">
  "Recovering the answer" is the most puzzling of them and it is **not an error**:
  that is how an answer the service is pulling back after a connection drop is
  marked. You can safely wait.
</Callout>

## Actions on a message

**Copy · Download as Markdown · Regenerate · Send again · Retry · Edit.**

<Callout type="tip">
  **"Download as Markdown" is the chat's least noticeable useful button.**
  A long answer leaves as a file with its markup, tables and code intact:
  handy when the answer has to go to a colleague or into documentation.
</Callout>

**Three cases where the buttons silently do nothing:**

- **"Retry"** works only for a **failed or cancelled** answer. On an ordinary
  finished answer it will not fire;
- **any action is blocked while an answer is being generated in this
  conversation**;
- **if the message had files and they are no longer available**, retry and edit
  will not work. You get "One or more chat attachments were not found, already
  used or unavailable" — an attachment lives for one message. The way out:
  send a new message and attach the files again.

**"Edit and send again" cuts the conversation from that message onwards** —
everything that came after disappears. This is a common loss: someone edits
an old question and loses the whole branch below it.

**An answer can be stopped mid-sentence, and nothing is lost.** The part
already written is kept, the message is marked "Cancelled", your question stays
in the thread, and "Retry" appears next to it. Pressing stop is not scary.

An empty message cannot be sent, but **a message consisting only of attachments,
with no text, can**.

## Conversations

On the left — the list: search, grouping by **Today / Yesterday / N days ago**,
renaming, deleting and "New chat". An unnamed conversation is called
"New conversation".

<Callout type="tip">
  **Conversations are stored on the server, not in the browser.** They are there
  from another device and after clearing the cache — just sign in to the same
  account.
</Callout>

There is also "Clear conversations" — deleting them all at once.

<Callout type="warning">
  Two caveats about clearing: **while an answer is being generated in any
  conversation, it will not run** — nothing happens at all, so wait for
  the answer first. And if even one conversation fails to delete, the list comes
  back as it was: there is no "half-deleted" state.
</Callout>

## If the chat answers with an error

| Message | What it means and what to do |
|---|---|
| "The current message does not fit into the selected model's context" | the conversation or attachment is longer than the model can read — start a new chat or take a model with a bigger context |
| "The selected model cannot work with images — choose another model or remove the picture" | the message names both ways out itself |
| "This file format is not supported" | the list of allowed formats is substituted into the message |
| "No more than N files can be attached to one message" | the limit is supplied by the server |
| "One or more chat attachments were not found, already used or unavailable" | an attachment lives for one message; attach the file again |
| "The chat history has changed. Refresh the chat and try again" | the conversation changed meanwhile — for example, it is open in a second tab |
| "The request is still processing" / "The request was already accepted" / "The request is already complete" | pressing again broke nothing and charged nothing twice |

<Callout type="tip">
  If a message looks technical — about an "invalid setting format" or
  a "value out of range" — it means the service refused an odd combination
  of parameters. The cure is the same: reset the chat settings and try again.
</Callout>

**Part of the chat interface is not translated.** On the English version
the "Ready-made prompts" and "System prompt" headings, the welcome line and
the role cards stay in Russian. Go by the icons and by this guide.
